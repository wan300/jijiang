# 09 - 开发规范

> 目标：统一团队协作方式，降低 Code Review、交接、二次开发成本。  
> 约束：所有开发者必须遵守；违反将在 Code Review 阶段被打回。

---

## 1. 通用原则

1. **约定优于配置**：能用默认就不自定义
2. **代码即文档**：命名清晰 > 写注释
3. **小步快跑**：一次 PR 聚焦一个变更；不超过 500 行 diff
4. **可测试**：核心业务逻辑必须有单元测试
5. **可回滚**：每次部署必须可快速回滚
6. **零容忍**：主分支不允许有编译/测试/lint 错误

## 2. 通用编码规范

### 2.1 命名

| 对象 | 规范 | 示例 |
| :--- | :--- | :--- |
| 包名 | 小写，不用下划线 | `com.jijiang.modules.order` |
| 类名 | 大驼峰 | `OrderService`、`OrderMain` |
| 接口 | 大驼峰，不加 `I` 前缀 | `OrderService` / `OrderServiceImpl` |
| 方法 | 小驼峰，动词开头 | `createOrder`、`findById` |
| 变量 | 小驼峰，见名知意 | `totalAmount`，避免 `a1`、`tmp` |
| 常量 | 全大写下划线 | `MAX_RETRY_COUNT` |
| 枚举类 | 大驼峰；值全大写 | `OrderStatus.WAIT_PAY` |
| SQL 字段 | 小写下划线 | `create_time` |
| 前端文件/组件 | kebab-case | `ji-service-card.vue` |
| CSS 类名 | kebab-case + BEM 可选 | `service-card__title` |

### 2.2 注释

- 注释解释 **"为什么"**，而不是 **"是什么"**
- 业务关键决策、非显而易见的实现，必须注释
- TODO/FIXME 必须写明处理时限与 owner：`// TODO(@zhangsan 2026-05-01): 重构为异步`
- 公共 API / 对外 DTO 必须有 JavaDoc

不好的注释：

```java
// 把 a 加 1
a++;
```

好的注释：

```java
// 防止并发下 used_stock 超过 stock，使用 SQL 的 WHERE stock > used_stock 行锁
int affected = mapper.decreaseStock(id);
```

### 2.3 代码组织

- 一个文件只做一件事；超过 500 行考虑拆分
- 函数长度 ≤ 80 行；嵌套层级 ≤ 4
- 禁止"魔法值"：必须抽常量或枚举

### 2.4 异常处理

```java
// ❌ 不要吞掉异常
try { doSomething(); } catch (Exception ignored) {}

// ❌ 不要用异常控制流程
try { return parse(s); } catch (Exception e) { return 0; }

// ✅ 抛出业务异常
if (order.getStatus() != WAIT_PAY) {
    throw new BusinessException(ErrorCode.ORDER_STATUS_ILLEGAL, "订单状态不允许支付");
}

// ✅ 捕获必须有日志与处理
try {
    wxPayClient.refund(...);
} catch (WxPayException e) {
    log.error("微信退款失败 orderNo={}", orderNo, e);
    throw new BusinessException(ErrorCode.REFUND_FAIL, "退款失败，请稍后重试");
}
```

### 2.5 日志规范

- 级别：
  - `ERROR` 需要人工介入（通知 / 告警）
  - `WARN`  可能是问题的信号
  - `INFO`  关键业务节点（下单、支付回调）
  - `DEBUG` 开发调试；生产默认不打开
- 格式：`[traceId] [userId] message key=value ...`
- **禁止**打印：Token、密码、身份证号、完整手机号
- 使用参数占位而非字符串拼接：

```java
log.info("用户下单 orderNo={} userId={} amount={}", orderNo, userId, amount);
```

### 2.6 数据库相关

- MyBatis 只用 `#{}`（参数化），禁用 `${}`，防 SQL 注入（排序字段白名单例外）
- 禁止 `SELECT *`；分页查询必须带 `ORDER BY id`
- 批量操作用 `foreach`，控制批次 ≤ 500
- 事务最短路径；避免跨服务 RPC 在事务内
- 数据库操作必须有索引验证（`EXPLAIN`）

## 3. Git 工作流

### 3.1 分支模型（GitFlow 简化版）

```text
main                  ← 生产，受保护，只能通过 PR 合并
├── release/v1.0.0    ← 预发
├── develop           ← 日常集成
│   ├── feature/user-login
│   ├── feature/order-pay
│   └── ...
└── hotfix/payment-bug  ← 紧急修复（直接从 main 拉）
```

### 3.2 分支命名

| 类型 | 前缀 | 示例 |
| :--- | :--- | :--- |
| 新功能 | `feature/` | `feature/order-refund` |
| 缺陷修复 | `fix/` | `fix/stock-concurrency` |
| 紧急修复 | `hotfix/` | `hotfix/wxpay-sign` |
| 重构 | `refactor/` | `refactor/order-service` |
| 文档 | `docs/` | `docs/api-spec` |
| 杂项 | `chore/` | `chore/bump-mybatis` |

### 3.3 Commit 规范（Conventional Commits）

```
<type>(<scope>): <subject>

<body 可选>

<footer 可选>
```

| type | 含义 |
| :--- | :--- |
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `docs` | 文档 |
| `style` | 格式（不影响功能） |
| `refactor` | 重构 |
| `perf` | 性能优化 |
| `test` | 测试 |
| `build` | 构建/依赖 |
| `ci` | CI/CD |
| `chore` | 杂项 |

示例：

```
feat(order): 增加订单超时自动取消

- 通过 Redis ZSet 延迟队列实现 15min 未支付自动关单
- 兜底定时任务扫描 expire_time 字段

Closes #123
```

### 3.4 PR（Pull Request）规范

**PR 标题**：遵循 Conventional Commits。

**PR 描述模板**（`.github/pull_request_template.md`）：

```markdown
## 变更说明
<!-- 本 PR 做了什么，解决什么问题 -->

## 关联 issue
Closes #

## 变更类型
- [ ] 新功能（feature）
- [ ] 缺陷修复（fix）
- [ ] 重构（refactor）
- [ ] 文档（docs）
- [ ] 其他

## 自测情况
- [ ] 本地编译通过
- [ ] 单元测试通过
- [ ] 接口联调通过
- [ ] 回归测试通过

## 影响范围
<!-- 数据库迁移？接口变更？配置变更？ -->

## 上线注意事项
<!-- 需要配合的运维操作 -->
```

**合并约束**：
- 至少 1 位 Reviewer 同意
- 所有 CI 检查通过
- 已解决所有 Reviewer 评论
- 分支 rebase 到最新 `develop`

### 3.5 禁止行为

- ❌ 直接向 `main`/`develop` 推送
- ❌ Force push 到共享分支
- ❌ 提交未解决的 `conflict` 标记
- ❌ 提交二进制、大文件（> 1MB 请走 OSS）
- ❌ 提交 `.env`、密钥、证书

## 4. Code Review 清单

### 4.1 功能正确性

- [ ] 需求/接口已完整实现
- [ ] 边界情况（空值、极值、并发）已考虑
- [ ] 错误路径有合适的异常与提示
- [ ] 幂等性已保证（特别是支付、退款、状态变更）

### 4.2 代码质量

- [ ] 命名清晰，避免缩写歧义
- [ ] 函数短小（≤ 80 行），单一职责
- [ ] 没有复制粘贴代码（抽取公共方法）
- [ ] 无魔法值（提取常量）

### 4.3 性能

- [ ] SQL 走索引（必要时附 `EXPLAIN`）
- [ ] 避免 N+1 查询
- [ ] 大数据量操作分批
- [ ] 缓存粒度与 TTL 合理

### 4.4 安全

- [ ] 输入已校验（`@Valid`）
- [ ] SQL 使用 `#{}` 参数化
- [ ] 用户行级权限检查（比如讲师改自己的服务）
- [ ] 敏感数据脱敏（日志、响应）
- [ ] 幂等键、签名已实现

### 4.5 可维护性

- [ ] 有单元测试（Service 层必测）
- [ ] 日志便于排查（关键字段齐全）
- [ ] 配置项外置（不硬编码环境信息）
- [ ] 注释说明"为什么"，非"是什么"

## 5. 测试规范

### 5.1 测试金字塔

```text
      ┌──────────┐
      │   E2E    │  少量（核心链路）
      ├──────────┤
      │  集成测试  │  中量（模块间）
      ├──────────┤
      │  单元测试  │  大量（每个 Service）
      └──────────┘
```

### 5.2 单元测试

**覆盖要求**：
- 业务 Service 类：行覆盖率 ≥ 70%
- 工具类（Util）：行覆盖率 ≥ 90%
- Controller：重点接口通过集成测试覆盖

**命名规范**：

```java
@Test
void should_create_order_when_stock_sufficient() { ... }

@Test
void should_throw_when_stock_not_enough() { ... }
```

**结构（AAA 模式）**：

```java
@Test
void should_refund_success_when_status_wait_confirm() {
    // Arrange
    OrderMain order = buildOrder(OrderStatus.WAIT_CONFIRM);
    when(orderMapper.selectById(1L)).thenReturn(order);

    // Act
    orderService.refund(1L, BigDecimal.TEN, "原因", OperatorType.BUYER, 100L);

    // Assert
    verify(refundMapper).insert(any(RefundRecord.class));
    verify(wxPayClient).refund(anyString(), anyString(), any(), any(), anyString());
}
```

### 5.3 集成测试（Testcontainers）

```java
@SpringBootTest
@Testcontainers
class OrderIntegrationTest {

    @Container
    static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.0").withDatabaseName("jijiang");

    @Container
    static GenericContainer<?> redis = new GenericContainer<>("redis:7.2-alpine").withExposedPorts(6379);

    @DynamicPropertySource
    static void props(DynamicPropertyRegistry reg) {
        reg.add("spring.datasource.url", mysql::getJdbcUrl);
        reg.add("spring.data.redis.host", redis::getHost);
        reg.add("spring.data.redis.port", () -> redis.getMappedPort(6379));
    }

    @Test
    void create_pay_confirm_flow() { /* ... */ }
}
```

### 5.4 接口联调

- 后端在 Knife4j 文档维护 Mock 示例
- 前端基于 Swagger/OpenAPI 生成 TS 类型（可选）
- 联调前双方确认：鉴权方式、入参字段、错误码、边界场景

## 6. 前端专项规范

### 6.1 TypeScript

- 尽量开 `strict: true`
- DTO / VO 必须定义类型，放在 `src/types/`
- 避免 `any`；必要时用 `unknown` + 类型守卫

### 6.2 Vue 组件

- 使用 `<script setup lang="ts">`
- Props 使用 `defineProps<T>()` 并给默认值
- Emit 明确类型 `defineEmits<{ (e: 'change', v: string): void }>()`
- 业务组件名 `ji-` 前缀；目录按功能分组

### 6.3 样式

- 全局变量在 `uni.scss` 定义（颜色、间距、字体）
- 样式 scoped，避免污染
- 优先使用 rpx 适配多屏；绝对定位谨慎

### 6.4 代码风格

- ESLint + Prettier 统一；`lint-staged` + `husky` 在 commit 前检查
- 文件 ≤ 400 行，组件 ≤ 300 行

## 7. 接口契约规范

### 7.1 定义流程

1. PRD 确认需求
2. 后端起草接口文档（Knife4j 注解）
3. 前后端在 Mock 环境共同 Review（30min 内完成）
4. 冻结文档后开始编码
5. 联调发现问题 → 先改文档再改代码

### 7.2 兼容性

- 向下兼容：新增字段可选；旧字段不能删
- 破坏性变更：升级 URL 到 `/api/v2/...`，保留旧接口 ≥ 1 个版本
- 错误码不允许复用

---

## 8. 依赖管理

### 8.1 后端

- 新增依赖需在 PR 说明理由
- 避免引入 GPL 类严格 license
- 定期 `mvn versions:display-dependency-updates`
- 重大版本升级（Spring Boot 3.x → 4.x）需技术委员会评审

### 8.2 前端

- 使用 `pnpm`，锁文件 `pnpm-lock.yaml` 入库
- 拒绝使用不再维护（> 1 年无更新）的库
- 每月 `pnpm outdated` 检查一次

## 10. 本地开发环境

### 10.1 最低版本要求

| 工具 | 版本 |
| :--- | :--- |
| JDK | 17 LTS |
| Maven | 3.9+ |
| Node.js | 20 LTS |
| pnpm | 8+ |
| Docker Desktop | 最新稳定版 |
| IntelliJ IDEA | 2024.1+ |
| HBuilderX / VS Code | 最新 |

### 10.2 IDEA 配置

- 代码风格：导入团队共享的 `codestyle.xml`
- 必装插件：Lombok、MyBatisX、MapStruct Support、CheckStyle、SonarLint
- 编码：`UTF-8`，行尾 `LF`
- Java → Code Style → 缩进 4 空格
- Git → 自动 Rebase

### 10.3 一键启动本地依赖

`scripts/dev-up.sh`：

```bash
#!/bin/bash
docker run -d --name dev-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=root mysql:8.0
docker run -d --name dev-redis -p 6379:6379 redis:7.2-alpine
```

### 10.4 Git Hook（husky / pre-commit）

```bash
# .husky/pre-commit
#!/bin/sh
. "$(dirname -- "$0")/_/husky.sh"

pnpm lint-staged
mvn -q checkstyle:check
```

检查：
- 代码风格（Checkstyle / ESLint）
- 禁用 `console.log` 入库（前端）
- 禁用 `.env`、`*.pem`、`*.key` 入库

## 12. 开发者 Checklist（提交前自查）

- [ ] 代码能通过 `mvn clean verify`
- [ ] 没有 `System.out.println` / 无用 `console.log`
- [ ] 没有 `TODO` 无 owner
- [ ] 没有被注释掉的代码块
- [ ] 没有打印敏感信息的日志
- [ ] 新增接口有 Knife4j 注解
- [ ] 新增字段有注释
- [ ] 新增表/字段有 Flyway 迁移脚本
- [ ] 新增配置有 `.env.example` 更新
- [ ] 已运行 lint；无告警
- [ ] 已运行单元测试；全部通过
- [ ] 更新了相关文档（API / README / 模块说明）
- [ ] 提交信息遵循 Conventional Commits
- [ ] PR 描述完整
