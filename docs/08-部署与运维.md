# 08 - 部署与运维

> 目标：**低成本、可复现、可观测**。学生团队可独立完成部署与日常运维。  
> 云服务：阿里云 / 腾讯云（二选一，文档以阿里云为例）

---

## 1. 环境规划

| 环境 | 用途 | 配置 | 域名 |
| :--- | :--- | :--- | :--- |
| `local` | 开发者本机 | Windows/Mac + Docker | `localhost` |
| `dev` | 集成联调 | 轻量服务器 2C2G | `dev-api.jijiang.com` |
| `staging` | 预发布（可选） | 轻量服务器 2C4G | `stage-api.jijiang.com` |
| `prod` | 生产 | 轻量/ECS 2C4G + RDS | `api.jijiang.com` |

> V1.0 阶段，可直接跳过 staging，只做 dev + prod 两环境。


```bash

```

### 3.3 防火墙 / 安全组

| 端口 | 协议 | 对外 | 说明 |
| :--- | :--- | :--- | :--- |
| 22 | TCP | 指定 IP 白名单 | SSH |
| 80 | TCP | 任意 | HTTP（跳转 HTTPS） |
| 443 | TCP | 任意 | HTTPS |
| 8080 | TCP | 仅本机/内网 | Java 应用 |
| 3306 | TCP | 仅本机 | MySQL |
| 6379 | TCP | 仅本机 | Redis |

**强约束**：生产环境禁止 MySQL/Redis 对公网开放，仅通过 Nginx 反代暴露必要服务。

## 4. 容器化部署（推荐）

### 4.1 Dockerfile（后端）

```dockerfile
# 多阶段构建：编译 + 运行
FROM maven:3.9-eclipse-temurin-17 AS builder
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline -B
COPY src ./src
RUN mvn clean package -DskipTests -B

FROM eclipse-temurin:17-jre-alpine
WORKDIR /app
RUN apk add --no-cache tzdata curl && \
    cp /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && \
    echo "Asia/Shanghai" > /etc/timezone
COPY --from=builder /app/target/jijiang-backend-*.jar app.jar
EXPOSE 8080
HEALTHCHECK --interval=30s --timeout=3s --start-period=30s --retries=3 \
  CMD curl -f http://localhost:8080/actuator/health || exit 1
ENTRYPOINT ["java", \
  "-XX:+UseContainerSupport", \
  "-XX:MaxRAMPercentage=75.0", \
  "-Dfile.encoding=UTF-8", \
  "-Duser.timezone=Asia/Shanghai", \
  "-jar", "app.jar"]
```

### 4.2 docker-compose.yml（V1 单机）

```yaml
version: "3.9"

services:
  mysql:
    image: mysql:8.0
    container_name: jijiang-mysql
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: jijiang
      TZ: Asia/Shanghai
    volumes:
      - ./data/mysql:/var/lib/mysql
      - ./conf/mysql/my.cnf:/etc/mysql/conf.d/my.cnf:ro
    ports:
      - "127.0.0.1:3306:3306"
    networks: [jijiang-net]
    command: >
      --default-authentication-plugin=mysql_native_password
      --character-set-server=utf8mb4
      --collation-server=utf8mb4_general_ci
      --ngram_token_size=2
      --slow_query_log=1
      --long_query_time=1

  redis:
    image: redis:7.2-alpine
    container_name: jijiang-redis
    restart: always
    command: >
      redis-server
      --requirepass ${REDIS_PASSWORD}
      --appendonly yes
      --maxmemory 512mb
      --maxmemory-policy allkeys-lru
    volumes:
      - ./data/redis:/data
    ports:
      - "127.0.0.1:6379:6379"
    networks: [jijiang-net]

  backend:
    image: jijiang/backend:${APP_VERSION:-latest}
    container_name: jijiang-backend
    restart: always
    depends_on: [mysql, redis]
    environment:
      SPRING_PROFILES_ACTIVE: prod
      DB_URL: jdbc:mysql://mysql:3306/jijiang?useUnicode=true&characterEncoding=utf8mb4&serverTimezone=Asia/Shanghai&useSSL=false
      DB_USERNAME: ${DB_USERNAME}
      DB_PASSWORD: ${DB_PASSWORD}
      REDIS_HOST: redis
      REDIS_PASSWORD: ${REDIS_PASSWORD}
      JWT_SECRET: ${JWT_SECRET}
      WX_APP_ID: ${WX_APP_ID}
      WX_SECRET: ${WX_SECRET}
      WXPAY_MCH_ID: ${WXPAY_MCH_ID}
      WXPAY_V3_KEY: ${WXPAY_V3_KEY}
      OSS_AK: ${OSS_AK}
      OSS_SK: ${OSS_SK}
    volumes:
      - ./logs:/app/logs
      - ./certs/wxpay:/data/cert:ro
    ports:
      - "127.0.0.1:8080:8080"
    networks: [jijiang-net]

  nginx:
    image: nginx:1.25-alpine
    container_name: jijiang-nginx
    restart: always
    depends_on: [backend]
    volumes:
      - ./conf/nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./conf/nginx/conf.d:/etc/nginx/conf.d:ro
      - ./certs/ssl:/etc/nginx/certs:ro
      - ./logs/nginx:/var/log/nginx
    ports:
      - "80:80"
      - "443:443"
    networks: [jijiang-net]

networks:
  jijiang-net:
    driver: bridge
```

### 4.3 Nginx 配置

`conf/nginx/conf.d/jijiang.conf`：

```nginx
server {
    listen 80;
    server_name api.jijiang.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name api.jijiang.com;

    ssl_certificate      /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key  /etc/nginx/certs/privkey.pem;
    ssl_protocols        TLSv1.2 TLSv1.3;
    ssl_ciphers          HIGH:!aNULL:!MD5;
    ssl_session_cache    shared:SSL:10m;

    add_header X-Frame-Options        "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff"    always;
    add_header Referrer-Policy        "no-referrer-when-downgrade" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    client_max_body_size 20m;

    limit_req_zone $binary_remote_addr zone=api_limit:10m rate=50r/s;

    location /api/ {
        limit_req zone=api_limit burst=100 nodelay;
        proxy_pass         http://backend:8080;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_connect_timeout 10s;
        proxy_send_timeout    30s;
        proxy_read_timeout    30s;
    }

    location /admin/ {
        # 可选：admin 接口 IP 白名单
        # allow 1.2.3.4;
        # deny all;
        proxy_pass http://backend:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location = /actuator/health {
        proxy_pass http://backend:8080/actuator/health;
        access_log off;
    }

    location / {
        return 404;
    }
}
```

```bash
# /opt/jijiang/scripts/backup.sh

  -uroot -p"${MYSQL_ROOT_PASSWORD}" \
  --single-transaction --quick --routines --triggers jijiang \
  | gzip > $BACKUP_DIR/jijiang-$DATE.sql.gz

find $BACKUP_DIR -name "jijiang-*.sql.gz" -mtime +30 -delete

# ossutil cp $BACKUP_DIR/jijiang-$DATE.sql.gz oss://jijiang-backup/mysql/
```

## 7. CI/CD 流水线

### 7.1 Git 分支策略

```
main      ← 生产，受保护
release/* ← 预发
develop   ← 日常集成
feature/* ← 功能分支
hotfix/*  ← 紧急修复
```

详见 [09-开发规范](./09-开发规范.md) §3。

### 7.2 GitHub Actions 示例

`.github/workflows/ci.yml`：

```yaml
name: CI

on:
  push:
    branches: [develop, main, 'release/**']
  pull_request:
    branches: [develop, main]

jobs:
  build-backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { java-version: '17', distribution: 'temurin', cache: 'maven' }
      - name: Build & Test
        run: mvn clean verify -B
      - name: Upload coverage
        uses: codecov/codecov-action@v4

  build-miniapp:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'pnpm' }
      - uses: pnpm/action-setup@v2
        with: { version: '8' }
      - run: pnpm install --frozen-lockfile
      - run: pnpm lint
      - run: pnpm build:mp-weixin
```

`.github/workflows/deploy.yml`（仅生产）：

```yaml
name: Deploy Prod

on:
  push:
    tags: ['v*']
  workflow_dispatch:

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with:
          registry: registry.cn-hangzhou.aliyuncs.com
          username: ${{ secrets.ALIYUN_DOCKER_USER }}
          password: ${{ secrets.ALIYUN_DOCKER_PASS }}
      - name: Build & Push image
        uses: docker/build-push-action@v5
        with:
          context: ./backend
          push: true
          tags: registry.cn-hangzhou.aliyuncs.com/jijiang/backend:${{ github.ref_name }}
      - name: SSH deploy
        uses: appleboy/ssh-action@v1.0.0
        with:
          host: ${{ secrets.PROD_HOST }}
          username: ${{ secrets.PROD_USER }}
          key: ${{ secrets.PROD_SSH_KEY }}
          script: |
            cd /opt/jijiang
            export APP_VERSION=${{ github.ref_name }}
            docker compose pull backend
            docker compose up -d backend
            docker compose ps
```

### 7.3 发布流程

```text
1. 开发者在 feature/xxx 分支开发 → PR → develop
2. develop 触发 CI，自动部署到 dev
3. 发版：develop → release/vX.Y.Z，测试通过后合并 main
4. main 打 tag vX.Y.Z → Deploy Prod 工作流
5. 生产冒烟测试（/actuator/health、关键接口）
6. 观察 30 min，无异常归档发布单
```

## 13. 备份与容灾

### 13.1 备份矩阵

| 对象 | 频率 | 保留 | 位置 |
| :--- | :--- | :--- | :--- |
| MySQL 全备 | 每日 02:00 | 30 天 | 本地 + OSS |
| MySQL binlog | 实时 | 7 天 | 本地 |
| Redis AOF | 实时 | - | 本地 |
| 配置文件 / 证书 | 变更时 | 永久 | Git Private |
| OSS 用户文件 | 云端自动多副本 | - | 阿里云 OSS |

### 13.2 容灾预案

| 故障 | RTO | RPO | 恢复策略 |
| :--- | :--- | :--- | :--- |
| 应用崩溃 | 5min | 0 | 自动重启 |
| 服务器宕机 | 30min | ≤ 5min | 新购服务器 → 恢复镜像 → 恢复 DB 备份 |
| DB 物理损坏 | 1h | ≤ 1h | 从 OSS 备份恢复 |
