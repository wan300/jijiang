# 02 - 数据库设计

> 数据库：MySQL 8.0+（InnoDB 引擎，utf8mb4 字符集）  
> 命名规范：小写下划线，表名单数（`user`、`order`），时间字段统一 `xxx_time`  
> 主键：所有业务表均使用 `BIGINT UNSIGNED` 自增主键 `id`  
> 通用字段：`create_time`、`update_time`、`is_deleted`（逻辑删除）

---

## 1. 命名与规范

### 1.1 命名规范

| 对象 | 规则 | 示例 |
| :--- | :--- | :--- |
| 数据库 | `jijiang` 或 `jijiang_{env}` | `jijiang_prod` |
| 表名 | 小写 + 下划线 | `service_item`、`order_main` |
| 字段 | 小写 + 下划线；避免保留字 | `create_time`、`user_id` |
| 索引 | `idx_<字段>` / `uk_<字段>`（唯一）/ `ft_<字段>`（全文） | `idx_user_campus` |
| 外键 | 物理上**不加外键约束**（性能考虑），逻辑上保证一致性 | - |

### 1.2 通用字段

每张业务表均包含以下字段：

```sql
`id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
`create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
`update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
`is_deleted`  TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除 1-已删除',
```

### 1.3 数据类型约定

| 业务含义 | 类型 | 备注 |
| :--- | :--- | :--- |
| 主键/外键 ID | `BIGINT UNSIGNED` | 避免溢出 |
| 金额（元） | `DECIMAL(10,2)` | 最大 99999999.99 |
| 短文本 | `VARCHAR(64/128/255)` | 按实际长度选择 |
| 枚举状态 | `TINYINT UNSIGNED` + 常量 | 应用层维护枚举 |
| 大文本/JSON | `TEXT` / `JSON` | V1 用 `JSON` 简化，避免过度建模 |
| 手机号 | `VARCHAR(32)` + 加密存储 | 密文，应用层解密 |
| IP | `VARCHAR(45)` | 兼容 IPv6 |

## 4. 核心表 DDL

### 4.1 `campus` 校区字典

```sql
CREATE TABLE `campus` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `name`        VARCHAR(128) NOT NULL COMMENT '学校名称',
  `short_name`  VARCHAR(32)  NOT NULL COMMENT '简称，用于搜索',
  `email_suffix` VARCHAR(64) DEFAULT NULL COMMENT '校园邮箱后缀，如 @xxu.edu.cn',
  `area_code`   VARCHAR(16)  DEFAULT NULL COMMENT '行政区划',
  `status`      TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '1-启用 0-关闭',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `is_deleted`  TINYINT UNSIGNED NOT NULL DEFAULT 0,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='校区/学校字典';
```


**订单状态枚举（常量表）**：

| 值 | 常量 | 含义 | 可流转到 |
| :-: | :--- | :--- | :--- |
| 10 | `WAIT_PAY` | 待支付 | 20 / 60 |
| 20 | `WAIT_ACCEPT` | 待接单 | 30 / 60（超时关闭） |
| 30 | `IN_SERVICE` | 进行中 | 40 / 70 |
| 40 | `WAIT_CONFIRM` | 待买家确认 | 50 / 70 |
| 50 | `DONE` | 已完成 | - |
| 60 | `CLOSED` | 已关闭（未支付/超时） | - |
| 70 | `REFUNDING` | 退款中（仲裁） | 80 / 50 |
| 80 | `REFUNDED` | 已退款 | - |

## 5. 索引与查询策略

### 5.1 索引设计原则

1. **高频查询字段**：建索引（如 `user_id`、`status`）
2. **复合索引**：最左前缀匹配，高区分度字段在前
3. **覆盖索引**：对于 count/list 接口，让索引包含所有查询字段
4. **全文索引**：仅对 `service_item.title/description` 启用，使用 ngram parser
5. **避免滥用**：每张表非必要索引 ≤ 5 个

### 5.2 典型查询模式

| 场景 | SQL 模式 | 索引 |
| :--- | :--- | :--- |
| 首页分类列表 | `WHERE campus_id=? AND category_id=? AND status=1 ORDER BY sales DESC` | `idx_campus_category` |
| 搜索 | `WHERE campus_id=? AND MATCH(title,desc) AGAINST(?)` | `ft_title_desc` + `campus_id` 过滤 |
| 用户订单列表 | `WHERE buyer_id=? AND status IN (...) ORDER BY create_time DESC` | `idx_buyer_status` |
| 讲师接单列表 | `WHERE seller_id=? AND status=20 ORDER BY create_time DESC` | `idx_seller_status` |
| 订单超时扫描 | `WHERE expire_time<NOW() AND status IN (10,20,40)` | `idx_expire_time` |
| 支付回调幂等 | `WHERE out_trade_no=?` | `uk_out_trade_no`（唯一） |

### 5.3 慢查询处理

- MySQL 开启 `slow_query_log`，阈值 500ms
- 每周由后端 leader 检查 slow log，给出 EXPLAIN 与优化方案
- 禁止 `SELECT *`；列表接口必须分页

## 6. 数据一致性与事务

### 6.1 事务使用约束

| 场景 | 事务隔离级别 | 策略 |
| :--- | :--- | :--- |
| 下单扣库存 | `READ_COMMITTED` | 行锁 `SELECT ... FOR UPDATE` 或 UPDATE 带条件 |
| 支付回调入账 | `READ_COMMITTED` | 幂等 + 事务；账户余额乐观锁 |
| 订单状态变更 | `READ_COMMITTED` | Service 方法 `@Transactional`；失败回滚 |
| 提现扣减 | `READ_COMMITTED` | 乐观锁 + 资金流水 |

### 6.2 幂等性保障

- **支付回调**：`uk_out_trade_no` 唯一索引 + 状态前置校验
- **退款**：`uk_refund_no` + `status` 前置校验
- **接口幂等**：客户端传 `idempotencyKey`，服务端 Redis `SETNX` 缓存 5min

### 6.3 最终一致性

- **订单完成 → 讲师账户入账**：同事务保证
- **订单完成 → 信誉分更新**：异步任务（评价完成时触发）
- **订单超时 → 自动取消**：定时任务扫描 `expire_time`；容忍 ≤ 1min 延迟
