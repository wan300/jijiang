# 10 - 迭代计划与里程碑

> 依据：产品立项书 §3.5 & §4.3  
> 方法论：MVP + 敏捷双周迭代；"单校验证 → 多校复制"  
> 总周期：6 个月（V1.0 → V3.0）

---

## 1. 版本路线总览

```text
         M1 ─── M2 ─── M3 ─── M4 ─── M5 ─── M6 ─── M7+
         │       │       │       │       │       │
        V1.0 破冰版       V2.0 社区版     V3.0 智能版
         │               │               │
    ┌────┴────┐     ┌───┴───┐        ┌───┴────┐
    · 登录认证   · 悬赏大厅     · 推荐算法
    · 发布下单   · 多维评价     · 站内 IM
    · 担保交易   · 讲师等级     · 二手资料
    · 基础评价   · 优惠券系统    · 校际复制
    · 小范围内测 · 后台数据看板  · 多校联盟
                · 全校铺开
```

| 版本 | 周期 | 目标 | 验收 |
| :--- | :--- | :--- | :--- |
| **V1.0 破冰版** | 第 1~2 月 | 跑通核心交易闭环 | 首月日活 ≥ 100，完成 ≥ 50 笔真实交易 |
| **V2.0 社区版** | 第 3~4 月 | 全校铺开，数据增长 | 月 GMV ≥ 4.5 万元（盈亏平衡） |
| **V3.0 智能版** | 第 5~6 月 | 智能推荐 + 多校复制 | 覆盖 ≥ 3 所高校，月 GMV ≥ 15 万 |

---

## 2. V1.0 破冰版（第 1 ~ 8 周）

### 2.1 目标

- 完成核心交易闭环：**微信登录 → 实名认证 → 发布服务 → 下单支付 → 订单履约 → 评价**
- 在 1 ~ 2 个学院内测，获取首批种子用户反馈
- 服务端/客户端具备上线生产能力

### 2.2 周度排期（Sprint 双周）

#### Sprint 1（第 1~2 周）：基建

| 任务 | 负责方 | 交付物 |
| :--- | :--- | :--- |
| 技术选型评审 | 架构 | ADR-001~004 |
| 项目初始化（后端 / 小程序 / 后台） | 全员 | 空壳工程 + README |
| 数据库建表脚本（V1 全部 18 张） | 后端 | `V1_0_0__init_schema.sql` |
| 基础设施搭建：Docker Compose（MySQL / Redis） | 后端 | `docker-compose.yml` |
| 微信小程序注册、AppID 申请 | PM | 凭证 |
| 云服务器采购、备案启动 | PM | 域名 + 备案号 |
| 虎皮椒支付配置 | PM | appid/appsecret + B 服务 notify_url |
| 请求 / 响应 / 异常 基础封装 | 后端 | `Result<T>`、`GlobalExceptionHandler` |
| 小程序请求封装 + Pinia 基础 | 前端 | `request.ts`、`useUserStore` |
| **交付 1**：数据库 SQL | 后端 | 含注释 |
| **交付 2**：`wx.login` 登录闭环 | 后端 + 前端 | 可获取 Token |

**扣分红线**：第 2 周末未完成登录闭环，延期一天扣 5 分。

#### Sprint 2（第 3~4 周）：核心交易

| 任务 | 负责方 | 交付物 |
| :--- | :--- | :--- |
| 实名认证（OCR 集成 + 人工审核） | 后端 + 前端 | 认证接口 + 审核页 |
| 服务发布（富文本、图片上传、价格配置） | 后端 + 前端 | 发布接口 + 发布页 |
| 服务检索（全文 + 分类 + 排序） | 后端 + 前端 | `/api/service/search` + 首页 |
| 服务详情页 | 前端 | 详情页 |
| 订单创建（幂等、库存扣减） | 后端 | `/api/order/create` |
| 订单状态机（10 → 20 → 30 → 40 → 50） | 后端 | `OrderStateMachine` |
| B 支付服务 + 虎皮椒回调验签 + A/B 幂等回推 | 后端 | `/api/payment/create` + B `/xunhu-notify` |
| 图片上传（OSS + 压缩 + 鉴权） | 后端 + 前端 | `/api/upload/oss-token` |
| **交付 1**：虎皮椒真实支付调通，B 回调 A 幂等 | 后端 | 联调通过 |
| **交付 2**：图片上传组件（前端限大小 2MB） | 前端 | 真机测试通过 |

**扣分红线**：第 4 周末未完成虎皮椒真实支付完整闭环（下单 → 支付成功 → 订单状态为 20），延期一天扣 5 分。

#### Sprint 3（第 5~6 周）：履约 + 评价 + 资金

| 任务 | 负责方 | 交付物 |
| :--- | :--- | :--- |
| 讲师接单、提交凭证、买家确认 | 后端 + 前端 | 完整订单流转 |
| 延迟队列（Redis ZSet）+ 超时任务 | 后端 | `DelayQueue` + 3 个 Job |
| 订单自动取消 / 自动确认 | 后端 | 单测 + 集成验收 |
| 站内信（纯文本 + 敏感词拦截） | 后端 + 前端 | 聊天页 |
| 评价提交 + 信誉分算法 | 后端 + 前端 | 评价页 + `credit_log` |
| 讲师虚拟账户 + T+1 冻结 | 后端 | 每日定时任务 |
| 退款（全额 + 协商） | 后端 + 前端 | 退款弹窗 + 对接微信 |
| **交付**：完整核心交易闭环联调通过 | 全员 | 录屏 + 走查 |

#### Sprint 4（第 7~8 周）：后台 + 内测 + 发布

| 任务 | 负责方 | 交付物 |
| :--- | :--- | :--- |
| 管理后台：实名审核、服务管理、订单监控 | 后端 + 后台前端 | 登录 + 3 个核心页 |
| 管理后台：仲裁工作台（全额退 / 部分退） | 后端 + 后台前端 | 仲裁功能 |
| 管理后台：提现审核 + 打款凭证 | 后端 + 后台前端 | 财务页 |
| 监控接入（Actuator + 日志） | 后端 | 健康检查通过 |
| 小程序审核提交 | 前端 | 通过微信审核 |
| 内测：1 ~ 2 个学院 50 名种子用户 | 运营 | 反馈表 |
| 爆款内容生产：10 ~ 15 个服务 | 运营 | 上架 |
| 上线 Checklist 走查 | 全员 | 生产稳定运行 |
| **V1.0 发布** | 全员 | Tag `v1.0.0` |

### 2.3 V1.0 验收标准

#### 功能验收（必测用例）

| 用例 | 步骤 | 通过标准 |
| :--- | :--- | :--- |
| UC-01 微信登录 | wx.login → 获取 Token | 3s 内返回；新用户自动建档 |
| UC-02 实名认证 | 上传学生证 → OCR 识别 | 置信度 ≥ 0.85 自动通过；否则入人工审核 |
| UC-03 发布服务 | 讲师填写并提交 | 敏感词拦截有效；上架成功 |
| UC-04 服务检索 | 首页 / 搜索 / 分类 | 300ms 内返回；排序合理 |
| UC-05 正常下单支付 | 下单 → 虎皮椒收银台 → 状态变 WAIT_ACCEPT | 支付成功后 3s 内订单状态更新 |
| UC-06 支付超时 | 下单后 15min 不支付 | 订单自动关闭 + 库存释放 |
| UC-07 讲师接单 / 交付 | 接单 → 上传凭证 → 买家确认 | 状态正确流转；资金入冻结账户 |
| UC-08 验收超时 | 讲师提交凭证后 7 天无操作 | 系统自动确认；讲师账户入账 |
| UC-09 退款 | 买家申请 → 仲裁 → 退款 | 金额正确原路返回 |
| UC-10 评价 | 订单完成后评价 | 信誉分正确变动 |
| UC-11 讲师提现 | 申请 → 后台审核 → 打款 | 余额正确扣减；资金流水完整 |
| UC-12 敏感词防跳单 | 站内信发"加我微信 138xxx" | 拦截并提示 |
| UC-13 并发抢购 | 2 人同时抢最后 1 库存 | 仅 1 人成功；另 1 人友好提示 |
| UC-14 账号注销 | 申请 → 7 天冷静期 → 硬删除 | 隐私字段清除；订单保留脱敏 |

#### 性能验收

- API P95 响应时间 ≤ 1s
- 单机支撑 200 QPS 无错误
- 首页首屏加载 ≤ 2s（4G 网络）

#### 业务验收

- 首月 DAU ≥ 100
- 首月真实交易订单 ≥ 50 笔
- 用户 NPS ≥ 40
- 无 P0/P1 生产事故

## 3. V2.0 社区版（第 9 ~ 16 周）

### 3.1 目标

- 全校铺开推广，DAU 提升 5 倍以上
- 引入运营工具、用户激励体系
- 通过数据看板支持精细化运营

### 3.2 功能清单

| 模块 | 功能 | 优先级 |
| :--- | :--- | :--- |
| **需求大厅** | 悬赏发布、讲师竞标、协商成交 | P0 |
| **多维评价** | 多标签、图文追评、讲师回复 | P0 |
| **讲师等级** | 青铜 / 白银 / 黄金 / 钻石 成长体系 | P0 |
| **优惠券** | 新人券、满减券、商品券 | P1 |
| **签到/任务** | 每日签到、任务奖励 | P2 |
| **后台数据看板** | DAU / GMV / 品类分布 / 讲师排行 | P0 |
| **订阅消息** | 订单关键节点模板消息推送 | P0 |
| **校园地推工具** | 活码、裂变海报 | P1 |
| **讲师/服务详情 SEO 优化** | 分享卡片、朋友圈/群 | P1 |

### 3.3 双周排期

#### Sprint 5（第 9~10 周）

- 悬赏大厅（发布 + 列表 + 讲师竞标）
- 多维评价 + 讲师回复
- 后台数据看板 v1（基础指标）

#### Sprint 6（第 11~12 周）

- 讲师等级（信誉分阶段 + 徽章）
- 优惠券模板 + 发券 + 使用
- 订阅消息（订单状态变更全量覆盖）

#### Sprint 7（第 13~14 周）

- 签到/任务
- 校园地推工具（活码、海报生成）
- 后台数据看板 v2（留存、转化漏斗）

#### Sprint 8（第 15~16 周）

- 性能优化（搜索缓存、图片 CDN、分包）
- 全校推广：班级群、社团合作、线下地推
- 舆情监控 + 危机公关演练
- **V2.0 发布** → Tag `v2.0.0`

### 3.4 V2.0 验收标准

- 月 GMV ≥ 4.5 万元（盈亏平衡点）
- MAU ≥ 3000（单校 1.5 万覆盖率 ≥ 20%）
- 复购率 ≥ 25%
- 平均订单客单价 30 ~ 80 元
- 讲师留存率（30 天）≥ 60%
- 生产事故 P0 = 0，P1 ≤ 2

## 4. V3.0 智能版（第 17 ~ 24 周）

### 4.1 目标

- 基于数据的精细化用户体验
- 完整 IM 能力，替代"加微信"沟通
- 多校复制，形成联盟效应

### 4.2 功能清单

| 模块 | 功能 | 备注 |
| :--- | :--- | :--- |
| **智能推荐** | 基于专业、年级、历史行为的个性化推荐 | 协同过滤 / 标签召回 |
| **站内 IM** | WebSocket 长连接、图文消息、已读回执 | 替代 V1 "手动刷新" |
| **校园二手资料流转** | 学长转卖笔记、考研资料 | 与技能并列的新品类 |
| **多校联盟** | 校际讲师互通（仅部分品类） | 跨校交易需二次确认 |
| **企业付款自动提现** | 升级到微信商户平台"企业付款到零钱" | 免去人工打款 |
| **校方合作嵌入** | 对接校团委、教务系统 | 朋辈导师认证 |
| **实时通知中心** | 消息聚合、优先级 | - |
| **讲师直播**（可选） | 讲师公开课（1v多） | P3 |

### 4.3 技术升级

| 项 | V2.0 | V3.0 |
| :--- | :--- | :--- |
| 部署 | 单机 Docker Compose | 多实例 + RDS + SLB |
| 应用 | 单体 | 模块化单体（按需拆分） |
| IM | 无 | WebSocket + Netty |
| 推荐 | 无 | 离线 + 在线（简单召回 + 排序） |
| 多校 | 单库单表 + campus_id | 考虑按 campus_id 水平分库 |

### 4.4 双周排期

#### Sprint 9（第 17~18 周）

- 站内 IM（WebSocket + 消息持久化 + 离线推送）
- 推荐系统 v1（基于专业标签召回）

#### Sprint 10（第 19~20 周）

- 二手资料流转（独立品类 + 审核流程）
- 推荐系统 v2（引入协同过滤）

#### Sprint 11（第 21~22 周）

- 多校架构演进（配置化校区、跨校交易规则）
- 企业付款接入（测试环境）
- 校方合作页面（备案材料嵌入）

#### Sprint 12（第 23~24 周）

- 复制部署到 2 所兄弟高校
- 运营联盟活动
- V3.0 发布 → Tag `v3.0.0`

### 4.5 V3.0 验收标准

- 覆盖高校 ≥ 3 所
- 月 GMV ≥ 15 万元
- MAU ≥ 1 万
- IM 消息日活 ≥ 60%（替代"加微信"）
- 推荐系统 CTR 提升 ≥ 20%

## 6. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
| :--- | :-: | :-: | :--- |
| 虎皮椒支付配置或域名审核延迟 | 中 | 高 | 立项第 1 周启动配置；保留人工联调环境 |
| ICP 备案延迟 | 中 | 高 | 立项第 1 周启动；备选：用备案中接入宽松策略 |
| 首批讲师质量差 | 中 | 高 | 邀请制 + 试讲课 + 运营自产 10~15 个爆款 |
| 冷启动无用户 | 中 | 高 | 校园地推 + 社群裂变 + 奖品激励 |
| 生产事故 | 低 | 中 | 监控告警 + Runbook + 回滚脚本 |
| 人员流失（学生团队） | 中 | 中 | 文档齐全；技术栈主流，易接手 |
| 校方异议 | 低 | 高 | 主动备案；合规红线严守 |

更多风险详见 [产品立项书 §4.4](./产品立项书.md)。

## 9. 发布流程

```text
1. 发布会议（发布前 1 天）
   - Owner 宣读变更点、影响面、回滚方案
   - 值班表、应急联系人、灰度策略

2. 正式发布（按窗口时间，建议工作日 10:00 或 15:00）
   - 合并 PR → Tag → 触发 Deploy
   - 小程序提审

3. 冒烟测试（发布后 15min）
   - 健康检查 OK
   - 关键接口手工走查（登录、下单、支付、评价）
   - 监控大盘观察

4. 观察期（发布后 24h）
   - 值班盯告警
   - 有异常立即回滚

5. 归档
   - 更新 CHANGELOG
   - 关闭 release/ 分支
```
