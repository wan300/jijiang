# 01 - 技术架构设计

> 适用版本：V1.0 ~ V3.0  
> 设计原则：**低成本、快迭代、易推广、可演进**

---

## 1. 设计原则

| 原则 | 解释 | 落地措施 |
| :--- | :--- | :--- |
| **低成本** | 学生团队预算有限 | 轻量应用服务器 + 阿里云学生优惠；单体后端；避免复杂中间件 |
| **快迭代** | MVP 1~2 个月上线 | 小程序热更新；DDD 轻量分层；约定优于配置 |
| **易推广** | 单校验证后多校复制 | 校区（`campus_id`）作为租户维度；配置化的佣金/分类 |
| **可演进** | 3~50 校可扩展 | 模块间通过接口解耦；易拆分为微服务；DB 按 `campus_id` 可分片 |
| **合规优先** | 涉及支付、实名 | 资金托管、三重审核、字段级加密、操作审计 |

### 2.2 分层职责

| 层 | 职责 | 典型组件 |
| :--- | :--- | :--- |
| 终端层 | UI 渲染、交互、调用 API | 小程序 / 管理后台 |
| 接入层 | 流量接入、TLS 终止、限流、WAF | Nginx、云厂商 WAF/CDN |
| 应用层 | 业务逻辑、鉴权、事务 | Spring Boot Controller/Service |
| 数据层 | 持久化、缓存、检索 | MySQL、Redis、OSS |
| 外部服务层 | 微信生态、个人支付 & AI 能力 | 微信开放平台、虎皮椒、百度 AI |

## 3. 技术栈决策矩阵

### 3.1 前端

| 决策点 | 选型 | 备选 | 决策理由 |
| :--- | :--- | :--- | :--- |
| 客户端形态 | 微信小程序 | 原生 App、H5 | 免下载、可社群裂变，支付通过后端拉起虎皮椒收银台 |
| 开发框架 | **Uni-app + Vue 3** | 微信原生、Taro | 一套代码多端，Vue 生态丰富 |
| 状态管理 | Pinia | Vuex | Vue 3 官方推荐，API 简洁 |
| UI 组件库 | uView Plus / uni-ui | - | 适配 Uni-app，移动端体验好 |
| 请求封装 | 基于 `uni.request` 封装 | axios | 避免在小程序中引入 axios 适配器 |
| 构建 / IDE | HBuilderX + CLI | VS Code | 官方推荐，支持真机调试 |
| 管理后台 | Vue 3 + Element Plus + Vite | React + Antd | 与小程序技术栈一致，降低心智 |

### 3.2 后端

| 决策点 | 选型 | 备选 | 决策理由 |
| :--- | :--- | :--- | :--- |
| 语言 | **Java 17** (LTS) | Go、Node.js | 校内学习成本低，可招募学弟学妹接手 |
| 框架 | **Spring Boot 3.2.x** | Spring Cloud、Vert.x | 单体足以支撑单校；社区成熟 |
| 鉴权 | Spring Security + JWT | Shiro、Sa-Token | 无状态、易水平扩展 |
| ORM | MyBatis-Plus | JPA / Hibernate | 易写 SQL、可控制；复杂查询场景友好 |
| 数据库 | MySQL 8.0 | PostgreSQL | 生态成熟、云厂商支持好 |
| 缓存 & 队列 | Redis 7.x | RabbitMQ、Kafka | 一个组件顶多个角色，降低运维 |
| 定时任务 | Spring `@Scheduled` | XXL-Job、Quartz | 初期规模足够，避免额外部署 |
| API 文档 | Knife4j + SpringDoc (OpenAPI 3) | Swagger 2 | 适配 Spring Boot 3，中文支持好 |
| 参数校验 | Jakarta Validation | 自定义 | 规范 + 注解 |
| 工具库 | Hutool、MapStruct、Lombok | - | 减少样板代码 |
| 日志 | Logback + MDC | Log4j2 | 默认集成，MDC 追踪链路 |
| 测试 | JUnit 5 + Mockito + Testcontainers | - | 单元测试 + 集成测试 |

### 3.3 中间件与基础设施

| 决策点 | 选型 | 备选 | 决策理由 |
| :--- | :--- | :--- | :--- |
| 云厂商 | 阿里云 / 腾讯云（二选一） | AWS、华为云 | 学生优惠、境内合规 |
| 计算 | 轻量应用服务器 2C4G → ECS 2C4G | 容器 / Serverless | MVP 阶段足矣 |

| 部署方式 | Docker + docker-compose（初期） | K8s | V1 单机即可，V3 再上 K8s |

| CI/CD | GitHub Actions / Jenkins (自建) | - | V1 可手动部署 |

## 4. 应用层分层架构

采用 **DDD 轻量化分层**，避免过度设计：

```text
┌─────────────────────────────────────────────────┐
│  Controller 层（REST 入口）                      │
│  · 参数接收与校验                                │
│  · 统一响应封装                                  │
│  · @Valid / @RequestBody                        │
└────────────────┬────────────────────────────────┘
                 │ DTO → Domain
┌────────────────▼────────────────────────────────┐
│  Service 层（业务编排 + 领域逻辑）               │
│  · 事务边界 (@Transactional)                    │
│  · 状态机、领域规则                              │
│  · 调用 Repository / RPC / 外部 API              │
└────────────────┬────────────────────────────────┘
                 │
┌────────────────▼────────────────────────────────┐
│  Repository / Mapper 层（持久化）                │
│  · MyBatis-Plus BaseMapper                      │
│  · 自定义 XML SQL（复杂查询）                    │
│  · 无业务逻辑                                   │
└────────────────┬────────────────────────────────┘
                 │
┌────────────────▼────────────────────────────────┐
│  Infra 层（基础设施）                            │
│  · Redis 客户端封装                              │
│  · 微信登录 / 虎皮椒支付 / OCR / 内容安全 SDK 封装 │
│  · 消息发送、文件上传                            │
└─────────────────────────────────────────────────┘
```

**强约束**：

1. Controller **禁止**直接调用 Mapper；必须经过 Service。
2. Service 之间可以互相调用，但**避免循环依赖**；跨模块调用通过接口。
3. DTO、VO、DO、Entity 必须独立，禁止"一个对象用到底"。
4. 外部 API 调用必须封装为 `XxxClient`，放在 `infra/client` 包下，便于 Mock。

## 5. 核心模块架构

### 5.1 八大模块依赖关系

```text
                        ┌──────────┐
                        │   admin   │（运营后台）
                        └─────┬─────┘
                              │ 读 / 管理
┌─────────────────────────────┼──────────────────────────────────┐
│                             ▼                                   │
│    ┌─────────┐     ┌─────────────┐     ┌──────────────┐        │
│    │ message │ ◀── │    order    │ ──▶ │   payment    │        │
│    └────▲────┘     └──────▲──────┘     └──────────────┘        │
│         │                 │                    │                │
│         │                 │                    ▼                │
│    ┌────┴────┐     ┌──────┴──────┐     ┌──────────────┐        │
│    │ review  │ ◀── │   service   │     │     risk     │        │
│    └─────────┘     └──────▲──────┘     └──────▲───────┘        │
│                           │                    │                │
│                    ┌──────┴──────┐             │                │
│                    │    user     │ ────────────┘                │
│                    └─────────────┘                              │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 模块一览

| 模块 | 核心职责 | 关键依赖 | 备注 |
| :--- | :--- | :--- | :--- |
| `user` | 登录、实名、RBAC、身份切换 | 微信登录、百度 OCR | 其他模块的基础 |
| `service` | 服务发布、检索、分类、库存 | user、risk | 全文索引 + Redis 缓存 |
| `order` | 订单状态机、超时调度、凭证 | service、payment | 延迟队列核心场景 |
| `payment` | A 侧支付摘要、订单入账、资金冻结、退款、提现 | B 支付服务 | A 不持有虎皮椒密钥 |
| `payment-server` | 虎皮椒下单、虎皮椒回调验签、真实支付流水、回推 A | 虎皮椒个人支付、Redis | 独立部署到 B 服务器 |
| `message` | 站内信、模板消息、存证 | user、order | 用于仲裁举证 |
| `review` | 双向评价、信誉分、标签 | order | 挂钩搜索权重 |
| `risk` | 敏感词、内容安全、防刷、脱敏 | user、service、message | 横切能力 |
| `admin` | 运营后台、仲裁、财务、看板 | ALL | 独立子项目或同仓库 |

## 6. 数据流与关键路径

### 6.1 核心写路径（下单支付）

```text
[小程序] ──▶ [Nginx] ──▶ [OrderController]
                              │
                              ▼
                       [OrderService]
                              │  校验库存 / 生成订单号
                              ▼
                       [MySQL 行锁扣减 stock]
                              │
                              ▼
                       [PaymentService]
                              │  HMAC 调用 B 支付服务
                              ▼
                       [Payment Server / B]
                              │  调用虎皮椒个人支付下单
                              ▼
                       [虎皮椒支付平台]
                              │  返回收银台/二维码 + 异步回调 B notify_url
                              ▼
                       [Payment Server / B]
                              │  虎皮椒验签 + HMAC 回推 A
                              ▼
                       [InternalPaymentCallback]
                              │  HMAC + nonce + 幂等
                              ▼
                       [OrderService.confirmPaid()]
                              │  状态机变更
                              ▼
                       [Redis ZSet 投递超时任务]
                              │
                              ▼
                       [MessageService 推送通知]
```

### 6.2 核心读路径（服务检索）

```text
[用户搜索] → 1. 优先查 Redis 缓存 (key: search:campus:kw:hash)
            → 2. 未命中 → MySQL FULLTEXT 查询
            → 3. 业务层计算综合排序分：
                 score = match*0.4 + credit*0.3 + sales*0.2 + freshness*0.1
            → 4. 结果写入 Redis，TTL 10min
```

## 7. 部署拓扑

### 7.1 V1.0 单机部署（推荐入门）

```text
                        ┌─────────────────────┐
                        │   微信小程序用户     │
                        └──────────┬──────────┘
                                   │ HTTPS
                        ┌──────────▼──────────┐
                        │   域名 + SSL        │
                        └──────────┬──────────┘
                                   │
                        ┌──────────▼──────────┐
                        │ 轻量应用服务器 2C4G │
                        │ ──────────────────── │
                        │  Nginx (80/443)     │
                        │   ↓ upstream        │
                        │  Java 应用 (8080)   │
                        │  MySQL (3306 本机)  │
                        │  Redis (6379 本机)  │
                        └──────────┬──────────┘
                                   │
                        ┌──────────▼──────────┐
                        │  OSS / COS (独立)    │
                        └─────────────────────┘
```

- **优点**：成本低（< 100 元/月）、部署简单、故障域集中
- **风险**：MySQL / Redis 与应用争抢资源；无容灾
- **缓解**：做好每日备份；磁盘快照；DB 只开本地端口

### 7.2 V2.0 分离部署（生产推荐）

```text
   [CDN + WAF]
        │
        ▼
   [SLB 负载均衡]
        │
    ┌───┴───┐
    ▼       ▼
  [App1]  [App2]   ← ECS，多实例横向扩展
    │       │
    └───┬───┘
        ▼
   [RDS MySQL 主从]
        │
        ▼
   [Redis 主从 / 集群]
        │
        ▼
   [OSS 私有 Bucket]
```

### 7.3 V3.0 容器化（可选）

- 应用容器化：Dockerfile + 多阶段构建
- 编排：docker-compose（单机）→ K8s (多校复制后)
- 配置中心：Nacos / Spring Cloud Config（可选）

## 8. 非功能性需求

### 8.1 性能目标（V1.0）

| 指标 | 目标值 | 说明 |
| :--- | :--- | :--- |
| API 平均响应 | < 300ms | 99% 请求 < 1s |
| 首页加载 | < 2s | 小程序首屏渲染 |
| 支付回调处理 | < 500ms | 保证幂等写入 |
| 单机并发 | ≥ 200 QPS | 单校 1.5w 用户足够 |
| 数据库连接池 | 20 ~ 50 | HikariCP |

### 8.2 可用性目标

| 指标 | 目标值 | 说明 |
| :--- | :--- | :--- |
| 月可用率 | ≥ 99.5% | 允许每月 ≤ 3.6h 不可用 |
| RTO（故障恢复） | ≤ 30min | 重启应用、切换 DB |
| RPO（数据丢失） | ≤ 5min | Redis AOF + MySQL binlog |

### 8.3 安全目标

- 全量 HTTPS，TLS 1.2+
- JWT Token 短有效期（2h）+ Refresh Token（7d）
- 敏感字段加密存储（手机号、身份证号）
- 实名图片私有 Bucket + 临时 URL
- 详见 [07-安全与风控设计](./07-安全与风控设计.md)

## 9. 演进路线

| 阶段 | 架构形态 | 触发条件 |
| :--- | :--- | :--- |
| **V1.0** | 单体 + 单机 + MySQL 本地 | MVP、1 校 |
| **V2.0** | 单体 + RDS + Redis 分离 + 多实例 | 5 ~ 10 校 |
| **V3.0** | 模块化单体 → 拆分核心模块为服务（可选） | ≥ 30 校 / GMV > 50 万/月 |

> **原则**：不过度设计；每一次架构升级必须由"可量化的瓶颈"驱动（CPU、DB 连接、慢查询、工单数量）。
